## Data Model: orders Table

Because `GET` uses `SELECT * FROM orders`, additional columns may exist in the table. Based strictly on fields referenced in this file, the following columns are used:

| Field Name        | Type            | Required (POST) | Required (PATCH) | Required (PUT) | Required (DELETE) | Notes |
|------------------|-----------------|-----------------|------------------|----------------|-------------------|------|
| order_id          | integer         | No              | Yes              | Indirect*      | No                | Used as identifier for confirm (PATCH). PUT updates `WHERE order_id = ?` using request field `id`. |
| ficha             | integer         | Yes             | No               | No             | No                | Inserted on POST |
| description1      | string          | Yes             | No               | Expected       | No                | Updated on PUT |
| description2      | string          | Yes             | No               | Expected       | No                | Updated on PUT |
| quantity          | integer         | Yes             | No               | Expected       | No                | Inserted/updated |
| quantity_unit     | string          | Yes             | No               | Expected       | No                | Inserted/updated |
| footage_quantity  | integer         | Yes             | No               | Expected       | No                | Inserted/updated |
| id                | integer         | No              | No               | No             | Yes               | DELETE uses `WHERE id = ?` (note: not `order_id`) |

\*PUT requires request field `id`, but uses it as `order_id` in the SQL `WHERE order_id = ?`.

Important inconsistencies to confirm before production use:
- `POST` reads `$data['order_id']` into `$id`, but does not insert it. Order IDs are likely auto-generated by the database.
- `PUT` uses request field `id` but updates by `order_id`.
- `DELETE` deletes using `WHERE id = ?`, not `WHERE order_id = ?`. This may be intentional (table has both fields) or a bug. The schema should be verified.

# GET Method

Returns all orders.

### Request
No request body required.

### Success Response
```json
{
  "success": true,
  "data": [
    {
      "order_id": 42,
      "ficha": 123,
      "description1": "Item A",
      "description2": "Variant B",
      "quantity": 10,
      "quantity_unit": "pcs",
      "footage_quantity": 250
    }
  ]
}
```

### No Orders Found
```json
{
  "success": false,
  "error": "No orders found"
}
```

### Example
```bash
curl -X GET "<BASE_URL>/orders.php" \
  -H "Accept: application/json"
```

# POST Method

Creates a new order.

### Required JSON Body
```json
{
  "ficha": 123,
  "description1": "Item A",
  "description2": "Variant B",
  "quantity": 10,
  "quantity_unit": "pcs",
  "footage_quantity": 250
}
```

### Missing Required Fields

HTTP 400
```json
{
  "error": "Bad Request",
  "details": "Missing required field(s)"
}
```

### Success Response

HTTP 201
```json
{
  "success": true,
  "data": "New item created successfully"
}
```

### Database Error

May return HTTP 200 with:
```json
{
  "success": false,
  "error": "Database error: <error message>"
}
```

### Example
```bash
curl -X POST "<BASE_URL>/orders.php" \
  -H "Content-Type: application/json" \
  -d '{
    "ficha": 123,
    "description1": "Item A",
    "description2": "Variant B",
    "quantity": 10,
    "quantity_unit": "pcs",
    "footage_quantity": 250
  }'
```

# PATCH Method

Confirms an order. The code comment indicates this:
- Updates order status
- Deducts from inventory


### Required JSON Body
```json
{
  "order_id": 42
}
```

### Missing order_id

HTTP 400
```json
{
  "error": "Bad Request",
  "details": "order_id is required"
}
```

### Success/Failure Status Codes
- HTTP 200 if `confirm_order()` returns `{ "success": true, ... }`
- HTTP 422 if `confirm_order()` returns `{ "success": false, ... }`

### Example
```bash
curl -X PATCH "<BASE_URL>/orders.php" \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": 42
  }'
```

# PUT Method

Updates an existing order.

### Required JSON Body

`id` is required and is used as the `order_id` in the SQL `WHERE order_id = ?`.

```json
{
  "id": 42,
  "description1": "Updated Item A",
  "description2": "Updated Variant B",
  "quantity": 15,
  "quantity_unit": "pcs",
  "footage_quantity": 300
}
```

### Missing id
```json
{
  "success": false,
  "error": "ID is required for update"
}
```

### Success Response
```json
{
  "success": true,
  "message": "Order updated successfully"
}
```

### Failure Response
```json
{
  "success": false,
  "error": "<error message>"
}
```

### Example
```bash
curl -X PUT "<BASE_URL>/orders.php" \
  -H "Content-Type: application/json" \
  -d '{
    "id": 42,
    "description1": "Updated Item A",
    "description2": "Updated Variant B",
    "quantity": 15,
    "quantity_unit": "pcs",
    "footage_quantity": 300
  }'
```

# DELETE Method

Deletes an order.

Important: The SQL is `DELETE FROM orders WHERE id = ?`. This uses column `id`, not `order_id`. Confirm the correct identifier column in your environment.

### Required JSON Body
```json
{
  "id": 42
}
```

### Missing id
```json
{
  "success": false,
  "error": "ID is required for deletion"
}
```

### Success Response (Deleted)
```json
{
  "success": true,
  "message": "Order 42 deleted successfully"
}
```

### Not Found
```json
{
  "success": false,
  "error": "No order found with ID 42"
}
```

### Example
```bash
curl -X DELETE "<BASE_URL>/orders.php" \
  -H "Content-Type: application/json" \
  -d '{
    "id": 42
  }'
```
